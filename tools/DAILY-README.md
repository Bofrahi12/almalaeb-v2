# الملعب V2 — التحديث اليومي للبيانات

## الفكرة في سطر

كل صباح يجلب `tools/daily-update.py` من **ESPN public API (بلا مفتاح، بلا اشتراك)**
مباريات اليوم + 4 أيام، ونتائج آخر 14 يوماً، والجداول، والهدافين، وتفاصيل كل
نتيجة (إحصائيات + أحداث الأهداف + الملعب) للدوريات الأوروبية الخمسة، ويدمج
البطولة المغربية من `data/botola-manual.json` (يدوي — ESPN لا يغطي البطولة
إطلاقاً: `mar.1` يعطي 404)، ثم يعيد بناء الموقع كاملاً.

## التشغيل اليومي

```bash
cd ~/workspace/almalaeb-v2 && python3 tools/daily-update.py
```

- **الوقت:** كل صباح بتوقيت المغرب، **قبل 12:00** (الأفضل ~09:00 — بعد صدور
  جداول/نتائج الليلة، وقبل ذروة الزوار).
- **المدة:** ~3 دقائق (حوالي 300 طلب ESPN — متوازية).
- **أمر الكرون** (يُنشئه الوكيل الرئيسي — لا يُنشأ من هنا):

```cron
0 9 * * * cd /home/hatch/workspace/almalaeb-v2 && /usr/bin/python3 -u tools/daily-update.py >> /tmp/almalaeb-daily.log 2>&1
```

## ما يجلبه السكربت (وكيف)

| البيانات | المصدر | الطريقة |
|---|---|---|
| مباريات قادمة / نتائج / مباشر | `site.api.espn.com/.../scoreboard?dates=YYYYMMDD` | يوماً بيوم: اليوم..+4 للمباريات، آخر 14 يوماً للنتائج |
| الجدول | `sports.core.api.espn.com/.../teams/{id}/record` | سجل كل فريق (لعب/فوز/تعادل/خسارة/له/عليه/نقاط) ثم فرز: نقاط ← فرق أهداف ← أهداف ← انتصارات |
| الهدافون | `.../seasons/2026/types/1/leaders` | أول 10، مع حلّ روابط اللاعب والفريق |
| تفاصيل نتيجة | `site.api.espn.com/.../summary?event={id}` | الاستحواذ/التسديدات/الركنيات + أحداث الأهداف والبطاقات + الملعب |
| البطولة | `data/botola-manual.json` | دمج كما هو — لا جلب تلقائي |

**أحداث الأهداف:** الهدف يُكشف بعلم ESPN نفسه `scoringPlay == true` — لا
بفلتر نوع الحدث (أنواع الأهداف متعددة: `goal`، `goal---header`،
`goal---penalty`، `penalty---scored`…؛ فلتر `startswith("goal")` كان يُسقط
ركلات الجزاء).

**ترجمة الأسماء:** الفرق عبر `data/logos.json` (الاسم الإنجليزي ← العربي، مع
تطبيع يزيل التشكيل والبادئات + خريطة استثناءات للأسماء المختلفة جذرياً مثل
Cologne=Köln). اللاعبون عبر `data/player-names.json` (157 اسماً، 19 نونبر
2026). أي لاعب جديد غير موجود في الخريطة يُعرض باسمه اللاتيني كما هو +
تحذير في الملخص — لا تُخترع ترجمة. أضف الاسم العربي يدوياً إلى الخريطة عند
ظهوره.

**الملاعب:** خريطة إنجليزي ← عربي داخل السكربت (~90 ملعباً). الملعب غير
الموجود يُعرض باسمه الإنجليزي كما هو (صحيح، غير مخترع).

**القنوات:** `beIN Sports` للدوريات الأوروبية الخمسة و`Arryadia TNT` للبطولة —
حاملا الحقوق في المغرب/الشرق الأوسط (ثابتة، ليست رقماً يُجلب يومياً).

## البطولة — التحديث اليدوي (5 دقائق كل صباح)

قبل تشغيل السكربت، افتح `data/botola-manual.json` وحدّث من جدول **FRMF.ma**
(أو ويكيبيديا 2026–27 Botola Pro المنقولة عن FRMF.ma):

1. حقل `updated` — تاريخ اليوم.
2. الجدول الكامل (16 فريقاً: المركز، لعب، فوز، تعادل، خسارة، له، عليه، نقاط).
   إن كان هناك خصم نقاط (مثل تمارة: −1 بقرار LNFP)، أضف `"deduction": 1` لصف الفريق.
3. الهدافون العشرة (اللاعب، الفريق، الأهداف).
4. مباريات الجولة القادمة (التاريخ + التوقيت بتوقيت المغرب) ونتائج الجولة الأخيرة.
5. إن لم يتغير شيء، يكفي تحديث `updated`.

إن كان الملف أقدم من 3 أيام يطبع السكربت تحذيراً واضحاً في الملخص. ملاحظة:
القرارات الانضباطية (مثل احتساب الوداد–تمارة 3-0 وخصم نقطة) لا تعكسها
المجمّعات فوراً — المصدر المرجعي هو FRMF.ma.

## الأمان — ماذا يحدث عند الفشل؟

- **فشل جلب دوري كامل** (شبكة/ESPN): السكربت يخرج بخطأ (`exit 1`) و**لا يمسّ
  البيانات القديمة إطلاقاً** — الموقع يبقى على بيانات أمس.
- **فشل تفاصيل مباراة واحدة** (summary): تُحفظ النتيجة بلا إحصائيات + تحذير،
  ويكمل التشغيل.
- **فشل التحقق** (عدد صفوف خاطئ، نقاط ≠ 3×فوز+تعادل−خصم، قيمة فارغة، مباراة
  مكررة): لا كتابة، لا بناء، `exit 1`.
- **فشل البناء**: تُسترجع نسخ البيانات القديمة تلقائياً.
- الكتابة ذرية (ملف مؤقت + `os.replace`) — لا ملف نصف مكتوب أبداً.

## المخرجات بعد كل تشغيل

- `data/leagues.json` + `data/fixtures.json` (المخطط نفسه كما كان).
- إعادة بناء كاملة عبر `tools/build-v2.py` (الصفحات + `data-fallback.js`).
- ملخص مطبوع: عدد مباريات اليوم/غداً/القادمة/النتائج، عدد النتائج
  بالإحصائيات والأحداث، التغييرات في الصدارة وأول 3 هدافين، والتحذيرات.

## حدود معروفة (لا تُحلّ بهذا السكربت)

- **توقيت المغرب — تنبيه تقني:** tzdata هذا الجهاز خاطئة للمغرب في 2026
  (تعطي `Africa/Casablanca` = UTC+0 في نونبر، والصحيح UTC+1) — لذلك يستخدم
  السكربت إزاحة ثابتة +1 مع استثناء رمضان (UTC+0) عبر جدول `RAMADAN_UTC0`
  في أعلى الملف (2026–2028). **حدّث الجدول كل سنة** (رمضان يتقدم ~11 يوماً
  سنوياً). إن أُصلحت tzdata الجهاز يوماً، يبقى السلوك صحيحاً.
- **لا نتائج مباشرة لحظية** (الدقيقة الحية): السكربت يعمل مرة في الصباح؛
  المباريات الجارية تظهر في `live` فقط إن صادف التشغيل وقت مباراة.
- **لا حكام**: ESPN summary لا يعطي الحكام — خانة الحكم تبقى «قيد التحقق».
- **لا تشكيلات ولا مواجهات مباشرة (H2H)**: تبويبا صفحة المباراة باقيان
  Placeholder صريحين.
- **فرز التعادل**: الفرز بالنقاط ثم فرق الأهداف ثم الأهداف. الليغا تعتمد
  المواجهات المباشرة أولاً عند تساوي النقاط — في حالة تعادل تام (نقاط + فرق
  أهداف + أهداف) قد يختلف الترتيب عن الرسمي؛ نادر، ويُصحح يدوياً إن ظهر.
- **البطولة يدوية بالكامل** — لا مصدر مجاني موثوق يغطيها آلياً (فُحص: ESPN
  404، وfootball-data.org لا يغطيها في الباقة المجانية).
